# 최소 편집 (원고 통합)

> 책쓰기 워크플로우 3단계. SKILL.md의 지시로 로드되는 실행 문서다. SKILL.md의 "최소 편집 원칙"과 "수정 권한 등급"을 반드시 먼저 따른다.

## 시작 전 준비

`{ACTIVE}/02_outline.md`를 읽고 각 장에 매핑된 에세이 파일을 확인한다.

## 활성 폴더 결정

```bash
ACTIVE=$(ls -1d draft/*/ 2>/dev/null | sort | tail -n 1)
ACTIVE="${ACTIVE%/}"
[ -z "${ACTIVE}" ] && { echo "활성 폴더 없음. /collect를 먼저 실행하세요."; exit 1; }
echo "활성 프로젝트 폴더: ${ACTIVE}"
```

## 세션 설정 (청크 단위 — 첫 호출에만 묻는다)

`{ACTIVE}/_session-config.json` 존재 여부로 판단한다. 없으면 `AskUserQuestion`으로 묻는다.

- 질문: "원고 통합을 어떤 단위로 진행할까요?"
- 옵션:
  1. **장 단위로 끊기 (권장)** — 한 장씩 통합하고 사용자가 다음 `/edit`를 다시 호출해야 진행
  2. **부 단위로 묶어서** — 한 부(여러 장)를 한 번에 진행
  3. **모두 한 번에** — 멈추지 않고 서문부터 결론까지 끝까지 진행

저장 형식은 book_publishing 스킬과 동일한 패턴을 따른다 (`chunk_unit`, `auto_continue` 키).

## 장별 통합 절차

각 장에 대해 다음을 순서대로 수행한다.

### 1. 원문 그대로 배치

매핑된 에세이 원문을 헤딩만 book-config 형식에 맞춰(예: "제1장. 원제목") 그대로 가져온다. 이 시점에는 한 글자도 바꾸지 않는다.

### 2. 병합 처리 (병합 대상으로 표시된 장만)

두 개 이상의 에세이를 한 장으로 합칠 때:
- 중복되는 문단은 하나만 남기되, **어느 원문에서 왔는지 변경 로그에 기록**한다
- 두 에세이의 논지가 어긋나는 부분이 있으면 **절대 임의로 봉합하지 않는다**. 변경 로그에 "🟡 상충 발견"으로 남기고 사용자에게 어떻게 처리할지 묻는다

### 3. 기계적 교정 (자동 반영)

- 오탈자, 명백한 비문(주어-술어 불일치 등), 띄어쓰기
- 인용 형식을 `book/book-config.md`의 "인용 스타일"에 맞춰 통일
- `book/book-config.md`의 "용어 통일" 목록 적용
- 모든 교정은 변경 로그에 원문/수정본을 나란히 기록한다

### 4. 연결 문단 추가

장이 바뀌는 지점(이전 장 끝 또는 이번 장 시작)에 **새로 쓴** 연결 문단을 추가한다.

- 분량: 2~4문장 정도. 길게 쓰지 않는다
- 목적: 서로 다른 주차에 쓴 에세이들이 하나의 책으로 읽히도록 논리적 다리를 놓는다
- 내용 제약: 이전 장/다음 장에 **이미 있는 논지**를 연결할 뿐, 새로운 주장이나 예시를 이 문단에서 창작하지 않는다
- 표시: 변경 로그에 "신규(연결 문단)"으로 명확히 구분해서 기록한다 (원문 수정과 섞이지 않도록)

### 5. 논지 수정이 필요해 보이는 부분

리뷰어가 아니라 통합 작업자 입장에서 "이 부분은 손보면 좋을 것 같다"는 판단이 들어도, 이 단계에서 **바로 고치지 않는다**. 변경 로그에 "제안(🟡)"으로만 남긴다. 실제 반영 여부는 `/review` 단계와 사용자 확인을 거친다.

## 청크 규칙

`book_publishing` 스킬과 동일한 패턴:
- 서문·부록을 포함해 장 단위로 별도 파일에 쓴다: `{ACTIVE}/03_manuscript-v1_ch01.md` 등
- 각 파일 완성 시 `<!-- STAGE_COMPLETE: 03_manuscript-v1_chNN -->` 마커
- 모든 장 완성 후 순서대로 병합해 `{ACTIVE}/03_manuscript-v1.md` 생성, 마지막에 `<!-- STAGE_COMPLETE: 03_manuscript-v1 -->`
- 대화가 끊기면 마커 없는 장 파일부터 이어쓰기 (절대 덮어쓰지 않음)

## 변경 로그 출력

`{ACTIVE}/03_change-log.md`에 SKILL.md "변경 로그 표준" 형식으로 전체 장의 수정 내역을 모은다. 장별로 섹션을 나눈다.

```markdown
|------|------|--------|------|------|------|

...
```

## 완료 처리

`chunk_unit`/`auto_continue`에 따라 안내 문구를 다르게 한다 (book_publishing 스킬과 동일 패턴).

`auto_continue: false`:
```
제N장 통합 완료. /edit로 다음 장을 진행하세요.
```

전체 완료 시:
```
원고 통합 완료 (변경 로그: draft/{ACTIVE}/03_change-log.md). /review로 리뷰 사이클을 시작하세요.
```

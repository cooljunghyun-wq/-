# 퍼블리싱 (검증 + Word 변환 + 메타데이터)

> 책쓰기 워크플로우 5단계. SKILL.md의 지시로 로드되는 실행 문서다.

## 시작 전 준비

`book/book-config.md`를 읽고 인용 스타일, 퍼블리싱 사양을 파악한다.

## 활성 폴더 결정

```bash
ACTIVE=$(ls -1d draft/*/ 2>/dev/null | sort | tail -n 1)
ACTIVE="${ACTIVE%/}"
[ -z "${ACTIVE}" ] && { echo "활성 폴더 없음. /collect를 먼저 실행하세요."; exit 1; }
OUT="output/${ACTIVE#draft/}"
mkdir -p "${OUT}"
echo "활성 프로젝트 폴더: ${ACTIVE}"
echo "출판 출력 폴더: ${OUT}"
```

## 1단계: 검증 (verify.py)

### 검증 스크립트

이 하네스의 표준 검증기는 **스킬 폴더의** `scripts/verify.py`다. 책마다 검증기를 따로 만들지 않는다.

```bash
python3 scripts/verify.py \
  "${ACTIVE}/05_manuscript-v2.md" \
  "book/book-config.md" \
  "${OUT}/verify-report.md"
```

- 종료 코드 0 → 다음 단계
- 종료 코드 1 → `{OUT}/verify-report.md`를 읽고 🔴 항목을 사용자에게 보고. 🔴이 0건이 될 때까지 본문을 직접 수정(기계적 수정에 한함)하거나 `/review` 4단계를 다시 돌린다

### 검사 항목

| # | 검사 | 심각도 |
|---|------|--------|
| 1 | em dash 잔존 | 🔴 (검증 규칙에서 허용 시 생략) |
| 2 | `**` 마크다운 잔존 | 🔴 |
| 3 | 어미 혼용 | 🟡 |
| 4 | 목차 항목 누락 | 🔴 |
| 5 | `<!-- STAGE_COMPLETE: 05_manuscript-v2 -->` 마커 존재 | 🔴 |
| 6 | 연결 문단 존재 여부 (장 시작부에 이전 장 참조 문구가 있는지 휴리스틱 검사) | 🟡 |
| 7 | 인벤토리의 모든 에세이가 본문 어딘가에 흔적이 있는지 (파일 경로 언급 없이도, 02_outline.md 매핑을 신뢰하고 개수만 대조) | 🔴 |
| 8 | 금지 용어 / 금지 영어 표현 | book-config 검증 규칙에 정의된 경우만 |
| 9 | 자가 채점 (10점 만점) | 정보 |

### 자가 채점 보고

```
verify 통과: 자가 채점 9 / 10 (🔴 0, 🟡 1)
```

9점 미만이면 출판을 보류하고 🔴 항목을 우선 정리할 것을 권장한다. 단, 이 스킬에서 🟡의 상당수는 "제안 미반영"이므로, 점수와 별개로 `pending-suggestions.md`를 사용자가 확인했는지가 실제 출판 가능 여부의 기준이다.

### 백업

검증 통과 시점의 `{ACTIVE}/05_manuscript-v2.md`를 `{ACTIVE}/_backup/05_manuscript-v2_published_$(date +%Y%m%d_%H%M).md`로 복사한다.

## 2단계: 미반영 제안 취합

`{ACTIVE}/04_review-*.md`의 모든 🟡/🟢 항목을 모아 `{OUT}/pending-suggestions.md`로 정리한다.

```markdown
# 미반영 제안 목록

이 원고는 최소 편집 원칙에 따라 출판되었습니다. 아래는 리뷰 과정에서 나온 "제안"이며,
논지나 표현을 바꾸는 내용이라 자동으로 반영하지 않았습니다. 필요하면 직접 검토해 반영하세요.

## 🟡 권장
| 위치 | 리뷰어 | 제안 내용 |
|------|--------|-----------|
| ... | 학술 엄밀성 | ... |

## 🟢 참고
| 위치 | 리뷰어 | 제안 내용 |
|------|--------|-----------|
```

이 파일을 만든 뒤 사용자에게 항목 개수를 한 줄로 보고한다.

## 3단계: Word 문서 생성

입력: `{ACTIVE}/05_manuscript-v2.md`

`book/book-config.md`의 "퍼블리싱 사양"에 따라 python-docx로 `{OUT}/final.docx`를 생성한다.

### 학술서 특유의 주의사항

- **각주(진짜 footnote)는 python-docx가 기본 지원하지 않는다.** book-config에서 "각주 사용: 예"로 되어 있으면 다음 중 사용자와 상의해 하나를 택한다:
  1. 장 끝 미주(endnote) 목록으로 대체 (구현 쉬움, 기본 권장)
  2. python-docx의 raw XML 삽입으로 실제 각주 구현 (구현 복잡, 문서 손상 위험이 있으므로 생성 후 반드시 Word에서 열어 확인)
- 참고문헌은 책 전체 통합 목록으로 마지막에 배치하고, book-config의 "참고문헌 정렬 기준"을 따른다
- 문서 작성자(author) 속성은 `book/book-config.md`의 저자명으로 설정
- 원 에세이에 있던 표/그림만 그대로 옮긴다 (새 이미지 생성 없음)

산출물: `{OUT}/final.docx`

---

## 4단계: 출판 메타데이터 생성 (선택)

학술 단행본은 트레이드북과 달리 마케팅 메타데이터가 필수는 아니다. 사용자가 요청한 경우에만 생성한다.

- 도서 분류: KDC/DDC 분류 시도 (있으면)
- 요약문: 목차와 서문 기반 3~5문장 (판매 카피가 아니라 학술서 소개문 톤)
- 키워드: 학술 데이터베이스 검색을 고려한 전문 용어 위주

출력: `{OUT}/metadata.md` (요청 시에만)

## 완료 처리

```
퍼블리싱 완료.
- ${OUT}/final.docx (최종 문서)
- ${OUT}/verify-report.md (검증 보고서, 자가 채점 X/10)
- ${OUT}/pending-suggestions.md (미반영 제안 N건 — 확인 권장)
```

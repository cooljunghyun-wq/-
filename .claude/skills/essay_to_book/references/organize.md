# 목차 설계 (essay → chapter 매핑)

> 책쓰기 워크플로우 2단계. SKILL.md의 지시로 로드되는 실행 문서다.

## 시작 전 준비

`book/book-config.md`의 "목차" 뼈대와 `{ACTIVE}/01_essay-inventory.md`를 읽는다.

## 활성 폴더 결정

```bash
ACTIVE=$(ls -1d draft/*/ 2>/dev/null | sort | tail -n 1)
ACTIVE="${ACTIVE%/}"
[ -z "${ACTIVE}" ] && { echo "활성 폴더 없음. /collect를 먼저 실행하세요."; exit 1; }
echo "활성 프로젝트 폴더: ${ACTIVE}"
```

## 매핑 원칙

1. **모든 에세이가 어딘가에 배치되어야 한다.** 인벤토리의 각 행은 정확히 하나의 장(또는 "제외" 목록)에 대응해야 한다
2. 같은 주제를 다룬 에세이가 여러 개면 **병합 후보**로 표시한다 (병합 자체는 `/edit` 단계에서 수행하되, 여기서는 "병합 대상"이라고만 표시)
3. `book/book-config.md`의 목차 뼈대에 있지만 대응하는 에세이가 없는 장은 **공백(gap)**으로 표시한다. AI가 그 공백을 새 글로 채우지 않는다 — 사용자에게 "이 장은 쓴 에세이가 없는데 어떻게 할지" 묻는다 (해당 장을 빼거나, 나중에 사용자가 직접 쓰거나)
4. 목차 뼈대에 없는 주제의 에세이가 나오면 **미분류**로 표시하고, 새 장/부로 넣을지 부록으로 돌릴지 사용자에게 묻는다
5. 에세이 원문의 작성 순서(날짜)와 책의 논리적 순서가 다를 수 있다. 논리적 순서를 우선하되, 순서를 바꾼 경우 그 사실을 명시한다 (연결 문단에서 티가 나지 않게 자연스럽게 이어야 하므로)

## 출력 규칙

`draft/{ACTIVE}/02_outline.md`에 다음을 기록한다.

```markdown
# 02. 목차 설계

## 부/장 구조와 매핑

### 서문
- 내용: (book-config 기준 서문 개요)
- 소스: 신규 작성 (서문은 예외적으로 AI가 초안 작성 가능 — 단, "이 책이 어떻게 만들어졌는지"에 한정하고 학술적 주장은 담지 않는다)

### 제1부: (주제명)
#### 제1장: (제목)
- 매핑 에세이: essays/20260302_행위자성.md (인벤토리 #1)
- 처리: 그대로 사용 / 병합 대상 (with 인벤토리 #4) / 순서 조정함

#### 제2장: ...

## 공백 (에세이 없는 장)
- (목차 뼈대에 있으나 대응 에세이가 없는 장을 여기 나열, 사용자 확인 필요)

## 미분류 (목차 뼈대에 없는 에세이)
- (해당 인벤토리 행 번호와 제안 위치)

## 병합 대상
- 인벤토리 #3 + #7 → 제3장으로 병합 제안 (사유: 같은 개념을 다른 주차에 재론)

<!-- STAGE_COMPLETE: 02_outline -->
```

공백/미분류/병합 항목이 하나라도 있으면, 마커를 달기 전에 `AskUserQuestion`으로 사용자에게 확인받는다. 확인 결과를 반영해 표를 확정한 뒤에만 마커를 단다.

## 완료 처리

```
목차 설계 완료 (N개 장, 공백 M개 확인됨). /edit로 원고 통합을 시작하세요.
```

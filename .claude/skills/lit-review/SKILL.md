# 문헌리서치 자동화 (lit-review)

이 skill은 저장소 루트의 `연구계획서.md`를 항상 먼저 참조 컨텍스트로 읽는다. 그 문서의 §4(RQ), §6(이론), §7(Study 1~4), §12(문헌리서치 자동화 전략 — 평가표/요약템플릿/DB스키마/키워드맵)이 이 skill의 모든 판단 기준이다. 연구모형이 바뀌면 `연구계획서.md`의 §13 변경이력에 먼저 기록한 뒤 이 skill의 판단 기준도 그에 맞춘다.

저장 위치 (저장소 루트 기준):
- `research/db/papers.csv` — 논문 DB (스키마: `연구계획서.md` §12.9)
- `research/summaries/<paper_id>.md` — 85점 이상 논문의 5쪽 표준 요약
- `research/digests/weekly-<YYYY-MM-DD>.md` — 주간 통합 메모 (75~84점 논문 + 이번 주 이론 변화)

## 처리 순서

### 1단계 — 입력 파악
사용자가 논문을 텍스트/PDF/링크/서지정보 중 무엇으로 주든, 최소한 다음을 확보한다: 제목, 저자, 연도, 저널, (가능하면) DOI, 초록 또는 본문. 정보가 부족하면 있는 것만으로 진행하되 어떤 필드가 비어 있는지 사용자에게 명시한다. **원문에 없는 결과나 수치를 절대 지어내지 않는다** — 확인 불가능한 항목은 "원문에서 확인 불가"로 표시한다.

### 2단계 — 100점 평가 (`연구계획서.md` §12.4)
7개 항목으로 채점하고 근거를 1줄씩 남긴다:

| 항목 | 배점 |
|---|---|
| 박사논문 직접 관련성 (4개 Study 핵심 변수·메커니즘과 연결) | 30 |
| 저널 수준 (§12.1 워치리스트의 A/A·B/B 등급 참고) | 15 |
| 학술적 영향력 (총 인용, 연평균 인용, citation velocity) | 15 |
| 최근성 (최근 3년 내 또는 최근 논쟁 촉발) | 10 |
| 이론적 중요성 (새 이론/통합모형/기존 이론 확장) | 15 |
| 방법론적 가치 (실험/패널/실제행동자료/다중연구) | 5 |
| 산업 적용성 (한국 섬유패션기업·정책·조사 적용 가능성) | 10 |

합산 점수에 따라 분기한다:
- **85점 이상** → 3단계(5쪽 요약) 진행, DB status = `Core` 또는 `Read`
- **75~84점** → 요약본 대신 1문단 핵심노트만 작성, `research/digests/weekly-pending.md`에 추가, DB status = `Skimmed`
- **65~74점** → DB에 메타데이터만 기록, DB status = `Inbox`
- **64점 이하** → 사용자에게 "낮은 관련성"이라고 짧게 알리고 원하면 메타데이터만 기록 (기본은 기록 생략)

### 3단계 — A4 5쪽 표준 요약 생성 (85점 이상, `연구계획서.md` §12.5)
아래 5개 섹션 구조로 `research/summaries/<paper_id>.md`를 작성한다. `<paper_id>`는 DOI를 슬러그화하거나(예: `10.1002-jfmm.2025.001` → `jfmm-2025-001`), DOI가 없으면 `저자연도-키워드` 형식으로 만든다.

1. **Executive Summary** — 한 문장 결론, 연구문제, 핵심 발견 3개, 본 박사논문과의 관련성
2. **Theory & Literature** — 사용 이론, 핵심 개념 정의, 기존 연구와의 차이, 연구가설/모형
3. **Method** — 표본, 국가, 데이터, 변수측정, 실험조건, 분석방법, 타당성
4. **Results & Contribution** — 주요 계수/효과(가능하면 효과크기·유의성 포함), 매개·조절, 이론적·실무적 기여, 저자 스스로 밝힌 한계
5. **Doctoral Research Memo** — 내 Study 1~4 중 어디와 연결되는지와 이유, 차용 가능한 척도/변수/가설/실험자극, replication 아이디어, research gap, 후속 연구질문 3개(한국 섬유패션산업 적용 아이디어 포함), 비판적 평가("이 논문이 못 보여준 것")

### 4단계 — DB 갱신
`research/db/papers.csv`에 한 행을 append/update한다 (파일이 없으면 헤더부터 생성). 컬럼은 `연구계획서.md` §12.9와 동일: `paper_id,title,authors,year,journal,tier,cluster,study_mapping,theory,method,sample_country,key_constructs,citation_metrics,relevance_score,key_finding,scale_source,research_gap,summary_link,pdf_link,status`. 같은 `paper_id`가 이미 있으면 덮어쓰지 말고 사용자에게 확인 후 갱신한다(중복 판단은 DOI 또는 제목 유사도 기준).

### 5단계 — 카카오톡 모닝 브리핑 (요청 시 또는 "브리핑 보내줘" 시)
`mcp__PlayMCP__KakaotalkChat-MemoChat` 도구가 사용 가능하면 사용한다(세션에 없으면 사용자에게 알리고 메시지 본문만 텍스트로 보여준다). 이 도구는 **메시지 최대 200자** 제한이 있으므로 `연구계획서.md` §12.7 형식을 아래처럼 압축한다:

```
[Research Brief MM/DD] <점수>점 <논문 축약제목>
핵심: <1문장 발견>
→ Study<n> 연결 / WTP·N/A
5쪽요약: research/summaries/<paper_id>.md
```

- TOP 3까지, 논문 1건당 메시지 1건씩 보낸다(200자 안에 들어가도록 축약; 링크는 저장소 내 상대경로로 충분).
- 오늘 요약된 논문이 없으면 브리핑을 보내지 않고 그 사실만 사용자에게 알린다(빈 메시지를 보내지 않는다).
- 매일 자동 스케줄 실행은 이 세션 자체에서는 하지 않는다 — 사용자가 스케줄을 원하면 `ScheduleWakeup`/트리거 설정은 별도로 상의한다(이 skill은 "요청받았을 때 브리핑을 만들어 보내는 것"까지만 담당).

### 6단계 — 주간/월간 롤업 (요청 시)
- **주간**(예: "이번 주 문헌 정리해줘"): `research/digests/weekly-pending.md`에 쌓인 75~84점 논문 + 이번 주 요약된 85점 이상 논문을 묶어 "이번 주 문헌이 기존 연구모형을 어떻게 바꾸는가"라는 2~3쪽 종합메모를 `research/digests/weekly-<YYYY-MM-DD>.md`로 작성하고, `weekly-pending.md`는 비운다.
- **월간**(예: "이번 달 정리해줘" / "연구계획서 업데이트해줘"): 그 달 Core 논문 중 핵심 10편과 이론/가설/변수에 실제 영향을 준 내용을 정리해 `연구계획서.md` §13 변경이력 표에 새 행을 추가할 것을 제안하고, 사용자가 동의하면 직접 반영한다. 임의로 연구모형(§4~7)을 고치지 않는다 — 반드시 사용자 확인 후 수정한다.

## 원칙
- 인용수 자체를 연구 질로 오인하지 않는다 — 연평균 인용·저널·이론적 중요성을 함께 본다.
- 원문에서 확인할 수 없는 결과·수치·인용정보를 절대 생성하지 않는다.
- 저작권·기관구독 정책을 준수한다 — 원문 PDF를 임의로 재배포하지 않고, 서지정보·초록·합법적 OA 원문만 다룬다.
- 논문 채점·요약은 항상 `연구계획서.md`의 최신 버전을 기준으로 한다. 이 md 파일이 갱신되면 다음 요청부터 새 기준을 적용한다.
